Organizations — search & filters

Wireframe for GRM-086. Binds IA and layout only (05_frontend rule 9a.2) — not colour, not copy, not component structure. Read with DESIGN §2.2.

The one decision this drawing exists to make. The organization list is a forest, not a table. A filter that returns matches alone flattens it, and a match without the line above it is not an answer — “Division Office” means nothing; “DOR → Provincial Office 1 → Division Office” is the answer. So matches keep their ancestors, and ancestors render as context: present, greyed, not counted.

Why no “parent organization” filter, though it was asked for. The tree is the parent relationship — the filter duplicates clicking a parent node, and it teaches the admin not to read the structure the screen exists to show. Dropped at intake (Q-02).

Two empty states, never one. “Nothing here yet” and “nothing matched” look identical and mean opposite things — an admin who cannot tell them apart concludes the screen is broken. The no-match state names the term and offers a way out; the no-data state offers Add an organization instead. Same rule already applied to the officer directory in GRM-087.

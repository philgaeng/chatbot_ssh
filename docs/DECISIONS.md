## What belongs here, and what does not

| | Where it goes |
|---|---|
| **What the system does today** | The live spec. Never here. |
| **Why a rule exists** | **In the spec, beside the rule** ([`engineering/06`](engineering/06_documentation_lifecycle.md) §5.1). Never only here. |
| **Why we chose A over B, and what would reverse it** | **Here.** |
| **Who did it, in which sprint, on which day** | The sprint folder — internal, not published. |
| **Every edit ever made** | `git log`. This is not a changelog. |

**One entry per real fork.** A decision with no rejected alternative is not a decision, it is a fact —
put it in the spec. Entries are append-only and dated; a reversal is a **new entry** that supersedes the
old one by number, never an edit to the original.

## D-001 · Staging holds synthetic data only

**Date:** 2026-09-04 · **Status:** decided, not yet enforced

**Chosen:** grievance data on the staging environment comes from the seeder only, under the reserved
`GRV-2025-*` / `CPL-2025-*` ID space, with an `ops` check that alerts on any row outside it.

**Rejected:** redacting screenshots and exports at the point of use. Images are not redactable in any
reliable way — the PII egress inventory already records the uploads volume as *"unchanged, and
unclosable"* for exactly this reason — so a control that depends on catching PII inside a picture
fails silently rather than loudly.

**Why it matters beyond privacy:** it is what allows a model to read a screenshot of the officer UI at
all, which is the difference between a triage tool that classifies text and one that can look at the
page.

**What would change the answer:** staging becoming a place where real grievances are filed — at which
point the invariant must either be re-established or the decision reversed explicitly, not eroded.

**⚠ Not covered by this decision:** staff identities. Staging is where production's Keycloak realm and
org chart are *authored*, so officer names and emails there are real.

## D-002 · The public repository is a generated copy, not the working repository

**Date:** 2026-09-04 · **Status:** decided, implementation pending

**Chosen:** the working repository stays private and carries every documentation tier; a **public**
repository carries tier 1 + 1b plus the root open-source files, generated by script from an explicit
prune list.

**Rejected:** one public repository containing everything. Sprint folders, adversarial reviews and the
operational logs are records of *process* — dated opinions, incident narratives, tech-debt scoring and
infrastructure identifiers — and none of them help a reader understand what the system does today.

**Consequence, accepted deliberately:** a live spec may no longer cite a sprint document
([`engineering/06`](engineering/06_documentation_lifecycle.md) §10.1). Where a spec relied on one for
its reasoning, the reasoning is folded into the spec (§10.2) or recorded here (§10.3) — **the pointer
is never simply deleted.**

**What would change the answer:** wanting external contributors to see the full working history, or a
DPG assessment requiring published process evidence. Neither applies today; the compliance pack in
[`dpg/`](dpg/) is published on its own merits.
